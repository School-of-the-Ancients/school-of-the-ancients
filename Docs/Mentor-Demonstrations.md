# Ask Galileo for a Matrix demonstration

Galileo can suggest a scene to help explain an idea. The suggestion is saved with the mentor reply and shown as a card containing its title, learning goal and complete scene request. A suggestion does not create anything by itself.

## From a question to a reviewed scene

1. Ask Galileo for a useful scene, for example: “Can you suggest a Matrix demonstration comparing how three block sizes affect volume?” A live mentor may return a **Build this demonstration** card when a scene helps the explanation. Ordinary questions still work without one.
2. Read the card's learning goal and scene request. Choose **Build this demonstration** when you want to send it. If Matrix is not connected, this opens the connection panel first. Pair using a temporary code from the Matrix Operator, then explicitly choose **Build this demonstration** again. Pairing never sends the suggestion automatically.
3. Matrix must advertise its reviewed Codex scene planner and provide a current writable runtime scene. Its planner prepares a proposal from the saved request. School displays planning separately from **Waiting for Operator review**; neither means the scene has been built.
4. Choose **Review in Matrix**. Inspect the exact proposed commands and their effects in the Operator. Apply there only when the proposal matches the demonstration you want. School has no Apply action.
5. Return to School and wait for the result, or choose **Check demonstration**. School records matched runtime command acknowledgments separately from the mentor's suggestion. Partial execution lists successful and failed command counts; a PC scene save is labeled separately from runtime execution.
6. Discuss the returned record with Galileo. For example: “What did that demonstration establish, and what does it not prove?” Asking a question, sending a scene request and receiving Matrix evidence do not advance the lesson or change the independent browser experiment.

Each saved mentor suggestion can create one scene-build request. Repeated clicks check that original request. Ask Galileo for a new suggestion when you want a different demonstration. Only the latest completed mentor suggestion for the current lesson step can start new work; old scene-build history remains available.

## Read the outcome honestly

- **Preparing proposal** means Matrix is planning. Nothing is confirmed as built.
- **Waiting for Operator review** means the proposal still needs Apply in Matrix.
- **Runtime confirmed** means the recorded command batch has matching successful runtime acknowledgments. It does not prove the scene still exists after later edits, establish measured physics, or assess learning mastery.
- **Some commands failed** means the batch completed only partly. Inspect its original Matrix request before deciding what to do next.
- **Matrix save confirmed** records a PC scene save. It is not proof that new objects appeared in the runtime.
- **Outcome unconfirmed** means School cannot safely establish the result. Use **Check demonstration** or **Inspect original Matrix**. Do not infer success or failure from the suggestion itself.

**Cancel before Apply** requests cancellation of a pending proposal. It does not undo dispatched commands. If a response is lost, **Retry the same request** retains its original identity and payload. School does not automatically repeat the build. Pending or uncertain Matrix work blocks additional scene changes while the text lesson remains usable.

Restarting School preserves its history but drops Matrix credentials. A new pairing cannot adopt or replay an old request. If the original request is no longer reachable, inspect its original Operator and resolve the scene manually before starting a new lesson. Historical links keep the original Operator address.

## Scope and prerequisites

The School mentor and Matrix scene planner are separate adapters. Configure Matrix's own Codex planner as well as the School mentor; a working School conversation does not establish Matrix planner availability. The existing Matrix pairing guide explains [local connection and review](Matrix-Bridge.md).

Scene requests are plain, inert text. The browser sends the saved mentor turn identity rather than an editable prompt, command list or executable script. Matrix owns planning, command validation and execution. Scene evidence remains separate from the [browser illustration and reviewed block-scale presets](Matrix-Scale-Lesson.md).

The bridge checks current Matrix room readiness. An aligned AR room may be eligible for a proposal, but this UI is not evidence of Quest or physical-room acceptance. No camera observation, physical measurement, validated physics or learning assessment is implied. The text lesson remains available with Matrix absent.
